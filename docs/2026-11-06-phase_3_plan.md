# codix — Phase 3 Step-by-Step Plan

Step-by-step plan for phase 3 (scopes and edits) of
`docs/2026-11-04-original_implementation_plan.md`, as that plan requires when a
phase starts. Task scope is the implementation plan's, with symbol aliases moved
in from phase 4 (see Known gap 1); this document adds the order of work, the
choices each task left open, and the steps inside each task. Each task lands as
one reviewed change, on its own branch, with its tests,
`cargo clippy --all-targets -- -D warnings`, `cargo fmt --check` and the full
test suite green on the three CI platforms.

## Choices made before phase 3

These were checked on 2026-11-06 against the pinned crates and the Rust 1.99.1
sources, not taken from memory.

| Question | Choice | Evidence |
| --- | --- | --- |
| `locals` queries (3.1) | codix writes its own `queries/locals.scm` for each of the 12 packs | Of the pinned grammar crates, only `tree-sitter-javascript` 0.25.0, `tree-sitter-typescript` 0.23.2 and `tree-sitter-ruby` 0.23.1 ship a `locals.scm`. They are written for highlighting: scopes, definitions and references only (the TypeScript one is 3 patterns), with no context kinds, namespaces or hoisting |
| Binding (3.1) | codix interprets the captures itself, in a new `codix-core::scope` module | As phase 1 does for `tags` (no `tree-sitter-tags`). Binding needs rules the captures alone don't carry: namespaces, hoisting, receivers, scopes that can hide members |
| What the index stores (3.1) | `refs` rows for references that can leave their file: bound to a symbol, or unbound. Local variables, parameters, their references and the scope tree are computed from the file when a command needs them | Commands about a local (def, refs, rename by location) read its file anyway, for freshness and region hashes, so the extra cost is one parse of one file. Locals are most of a file's identifiers, and nothing outside the file can refer to them. Index size, cold index time and that per-file cost are measured on spring-framework in 3.1a (see Open points) |
| Locals and symbol IDs (3.1) | Locals get no symbol ID; commands name them by `file:line:col` | An ID is language, path, qualified name and a hash of kind and signature: two `for (int i …)` loops in one method would share an ID |
| Unified diff (3.3) | Generated from the edit set, std only | codix knows every changed range, so hunks need no diff algorithm (no `similar` crate) |
| Replacing files on Windows (3.6) | `std::fs::rename`, retried briefly, instead of `ReplaceFileW` | The workspace forbids `unsafe`, and `ReplaceFileW` is only reachable through `windows-sys`, unsafe. In Rust 1.99.1, `std::fs::rename` on Windows is `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`, falling back to `FileRenameInfoEx` with POSIX semantics on access denied (`library/std/src/sys/fs/windows.rs`). Trade-off: `ReplaceFileW` keeps the target's ACL, creation time and alternate streams; a renamed temp file has the ACL its directory gives it, and codix copies the read-only attribute itself |
| Rebasing a preview (3.6) | Apply reruns the preview's planner on the current files and accepts the new edit set when its regions match the planned ones | A preview records hashes and edited regions, not whole files (design), so there is no old text to diff against. Re-planning also reruns the pre-flight checks against the current index, as the design requires |
| Identifier validity (3.4) | `regex`, already a dependency, with `\p{XID_Start}` and `\p{XID_Continue}` | `regex-syntax` 0.8.11 has both property tables |
| Preview IDs (3.3) | 8 hex digits of BLAKE3 over time, process ID and a counter; checked unique on insert | No RNG crate needed |
| Journal durability (3.6) | The journal entry commits with `PRAGMA synchronous = FULL` before any file is written; each temp file is fsynced before its rename | WAL with the default `NORMAL` survives a killed process but can lose the last commit on power loss; the journal must not |

### Crate versions

No new crate is expected. If a task turns out to need one, it is added then,
at its latest release, and this table gains a row.

### Sandbox

Nothing new: apply, the journal and crash recovery use files and processes the
sandbox allows. Tests through a daemon keep the `live_` prefix and run on CI.

## Known gap 1: aliases arrive after renames

Decided: symbol aliases move into phase 3, as task 3.7, so the first applied
rename already leaves a trail. Without them, an agent that chains an ID from
before a rename gets `unknown_symbol`, and `undo` has no alias to remove.

Only renames write aliases in phase 3. Tombstones and `symbol_deleted` stay in
phase 4 with `safe-delete` (4.7), their only writer. Phase 4's task 4.5 shrinks
to those.

Moving it renumbers the tasks after `apply`: the implementation plan's 3.7
(`previews`, `discard`, expiry), 3.8 (`undo`) and 3.9 (phase exit) become
3.8, 3.9 and 3.10 here.

## New modules

No new crate. In `codix-core`:

- `scope`: the file model. Parse a file, build its scopes, definitions and
  references, and bind them.
- `edit`: edit sets, regions, diffs, previews, pre-flight checks, apply, the
  journal and aliases.

## Order of work

Tasks run in the order below. Dependencies that decide where code first
appears:

  - 3.1b: Python, JavaScript, TypeScript (with TSX) and Kotlin;

- **3.7 needs 3.6**, which writes the aliases; **3.9 needs 3.6 and 3.7**.

## Tasks

### 3.1 Tier 2 extraction

1. **Pack interface.**
   - `register!` gains an optional `locals` query (`queries/locals.scm`), and
     `Grammar` its text. A pack with one is at tier 2.
   - The grammar fingerprint covers the `locals` query, so every file of the
     pack is reparsed when it changes.
   - The descriptor gains a `[scopes]` table:
     - `namespaces`: which definition kinds share a namespace, and which one
       each reference context reads. Java has types, methods and values;
       Python has a single namespace.
     - `hoisted`: scope kinds whose definitions are visible before their
       position, such as JavaScript functions and `var`, Python function scopes,
       Go package scope and Java class bodies. In other scopes, a reference sees
       only earlier definitions, and the latest one wins, as Rust's `let`
       shadowing requires.
     - `self_receivers`: `this`, `self`, `$this`. Member access through one of
       them binds to the members of the enclosing type.
2. **Captures.** tree-sitter's names, with codix suffixes:
   - `@local.scope.<kind>` (function, class, block, module), with
     `(#set! local.opaque)` on scopes where a name not found may be a member
     codix cannot see. Examples:
     - a Java class with an `extends` clause, or an anonymous class;
     - a Kotlin lambda with a receiver;
     - a C# `partial` class;
     - a JavaScript `with` block;
     - a Ruby class that includes a module.
   - `@local.definition.<kind>` for parameter, variable and import. Tier 1
     symbols are definitions in their enclosing scope, without a capture.
   - `@local.reference.<context>` for call, type, import, read and write, and
     `@local.receiver` on the object of a member access.
3. **Binding**, in `scope`. A reference is looked up from its scope outward,
   in the namespace its context reads, and ends in one of three states:
   - **bound** to a symbol or a local;
   - **free**: no definition in the file. Builtins and cross-file names end
     here, and so does member access through any receiver other than a self
     receiver;
   - **uncertain**: an opaque scope lies between the reference and the outer
     definition that would match. In Java, an inherited member hides a member
     of the outer class, and tier 2 cannot see inherited members.

   Codix never guesses: an uncertain reference is not bound.
4. **Index**, migration 5.
   - `refs` table: file, name, context, range, enclosing symbol ID, target
     symbol ID (null when free or uncertain), state and confidence.
   - Indexed by name, by target and by file.
   - References bound to locals are not stored, and neither are scopes (see
     Choices).
5. **Parse errors.** References in or around an error region are marked low
   confidence, by the same rule as symbols (`in_error`).
6. **Tiers.** `Tier` gains `scopes`. `capabilities` and `languages` show it,
   and each operation lists the tier it needs (additive schema change).
7. **Corpus.** `corpus/<language>/<case>.<ext>.scopes` holds one line per
   reference: `line:col context name -> line:col | free | uncertain`.
   - Rules that every language exercises:
     - sequential and hoisted scopes;
     - nested shadowing;
     - parameters;
     - closures and lambdas;
     - members through an implicit receiver and through a self receiver;
     - opaque scopes;
     - imports.
   - Rules for single languages:
     - Python: `global`, `nonlocal`, comprehension scopes, and class scope not
       enclosing its methods;
     - JavaScript and TypeScript: `var` against `let`, and type space against
       value space;
     - Go: `:=` redeclaration;
     - Rust: `let` shadowing, and macro bodies having no references;
     - C and C++: preprocessor bodies having no references;
     - PHP: `use` in closures, `global`;
     - Ruby: an assignment introduces a local, and a bare name is otherwise a
       method call;
     - Kotlin: `it`;
     - C#: `partial`.

**Tests:**

- the corpus of each language;
- a changed file has its `refs` rows replaced;
- a pack upgrade reparses its files;
- in 3.1a: cold index time, index size and the parse time of one file on
  spring-framework, reported to you before 3.1a merges.

### 3.2 `refs` and `def` by location

1. **Freshness.** `grep`'s "complete or rescan" step becomes a helper used by
   `grep`, `refs` and edit planning. A daemon whose watcher covers every
   directory flushes its pending batch; otherwise a no-change scan runs, and
   `possibly_stale` is set when the lock stays busy. Lookups keep their phase 1
   recheck.
2. **`refs <symbol>`.** The symbol is given by ID, path part or name (with the
   ambiguity rules of `def`), or by location. A location means the binding of
   the identifier there, a local included, read from the current file. Results:
   - the definition, context `def`;
   - in the definition's file, the references bound to it: `scoped`;
   - free and uncertain references with the same name, in other files and in
     the same file: `textual`. A local or a file-private symbol has none.
   - Files at tier 1: whole-word matches of the name, `textual`. No compiled-in
     code language stays at tier 1 after 3.1, so tests use a test-only pack
     registered by `codix-testkit` with a `tags` query and no `locals`.
3. **Output.**
   - Text as in the design's example: location, context, enclosing symbol,
     confidence; then a footer such as `3 references (2 scoped, 1 textual)`.
   - JSON: groups by file, each reference with location, context, confidence
     and enclosing symbol; totals; `possibly_stale`.
   - Scope flags (`--path`, `--here`) and paging as in `find`. Sorted:
     definition first, then its file, then by path.
4. **`def` by location.** The identifier at the location decides:
   - bound: its definition. A local answers in a new `local` field (name,
     kind, location) with `symbols` empty, which is an additive change.
   - free or uncertain: the name is looked up as `def <name>` does, and each
     result is marked `textual` (`SymbolResult` gains `confidence`).
   - no identifier at the location: as today, the innermost enclosing symbol.
5. **Frontends.** The new `refs` operation is in the dispatch table, with a
   description, CLI flags, an MCP tool and schema snapshots.

**Tests:**

- golden `refs` output for each confidence, for a local, and for a type's
  member;
- `def` on a reference, on a definition, on a free name, and away from any
  name;
- a reference added in another file without `index` is found (no-change
  scan), and the same through a daemon (`live_`);
- parity between the CLI and the daemon, and between the CLI and MCP.

### 3.3 Edit engine

1. **Model.**
   - An edit is a file, a byte range and a replacement. An edit set is sorted
     per file; overlapping edits are an internal error.
   - A region is the whole lines an edit touches: its line range and its
     bytes.
   - A planned file is a path, its BLAKE3 hash, and its regions.
2. **Line endings.** A newline in a replacement takes the ending of the line it
   lands in, so an edit never changes a file's line endings.
3. **Applying to text** is one pure function, used for the diff, for the
   simulated edit of the pre-flight checks, and by `apply`.
4. **Diff.**
   - Unified, with 3 lines of context, and hunks merged when their contexts
     overlap.
   - Paths are root-relative, with `a/` and `b/` prefixes, so `git apply`
     accepts the diff.
   - `\ No newline at end of file` where it applies.
5. **`previews` table**, migration 6: ID, creation time, operation, request
   (JSON), edits, planned files, overrides and summary. Planning writes the
   row in its own short transaction, without the write gate.
6. **Preview output**, shared by `rename`, `undo` and phase 4's commands:
   - the preview ID;
   - the summary: files, sites, each override used with its sites, the
     excluded sites with their reason, and the ambiguous sites;
   - the diff;
   - the next step. The CLI prints `codix apply <id>`; MCP names the `apply`
     tool with its `id`, the way phase 2's hints name tools.

**Tests:**

- regions, CRLF and mixed line endings, multibyte columns;
- golden diffs: merged hunks, an edit on the last line without a newline;
- a preview row round trip.

### 3.4 Pre-flight checks

1. **Pack rules**, in a new `[names]` descriptor table:
   - `identifier`: a regex, by default `^[\p{XID_Start}_]\p{XID_Continue}*$`.
     Packs override it where their language differs, such as `$` in Java and
     JavaScript names.
   - `keywords`: reserved words.
   - `type_keywords`: words reserved only as type names, such as Java's `var`,
     `record` and `yield`.
   - `visibility_by_case` (Go): an initial capital exports a name.
   - `constructors_named_after_type`: Java, C#, C++ (with `~` destructors).
   - `file_named_after`: definitions whose name the file name must match, such
     as Java public top-level types and a Rust `mod x;` without a body.
2. **Checks**, in this order. The first that fails refuses the plan with its
   code, every affected site, and the override that allows it, if one exists.
   All codes exit with 4.

   | Code | Condition | Override |
   | --- | --- | --- |
   | `invalid_name` | Not an identifier, a keyword, or a type keyword for a type; or the simulated edit leaves new parse errors | none |
   | `parse_error_region` | A site in or around a parse-error region | none, ever |
   | `renames_file` | The name is tied to the file name | none: moving files is not a phase 3 edit |
   | `name_collision` | A definition with the new name in the target scope and namespace | none. In languages with overloading, a method name already used is a collision unless `--allow-overload` |
   | `shadowing` | Simulated rebinding: apply the edits in memory, bind again, and compare. A reference that bound elsewhere now binds to the renamed definition, or one that bound to it now binds elsewhere. Both directions are reported, each site with its direction | `--allow-shadowing` |
   | `visibility_change` | A Go rename that changes the case of the first letter | `--allow-visibility-change` |
   | `tier_too_low` | A site in a file below the tier the edit needs | `--textual` (tier 1 renames) |
   | `unresolved_sites` | References that may mean the symbol but that codix cannot bind: same-name references in other files, uncertain references, member access through another receiver | `--exclude-unresolved`: edit the bound sites only, leaving those unchanged |
   | `generated_code` | A site in a generated or vendored file | `--allow-generated` |

   Comparing bindings instead of encoding each language's shadowing rules
   makes the check follow the same model as the binding itself.
3. **Generated and vendored code.**
   - Version control descriptors gain `generated_attributes`. Git reads
     `linguist-generated` and `linguist-vendored` from `.gitattributes` files,
     matching their patterns with the `ignore` crate's gitignore matcher.
   - Build descriptors gain `generated` path patterns: for Maven,
     `target/generated-sources/**` and `target/generated-test-sources/**`; for
     Gradle, `build/generated/**`.
   - Language packs gain `generated`, for the conventions of their ecosystem:
     - header markers, matched in a file's first lines: Go's
       `^// Code generated .* DO NOT EDIT\.$`, C#'s `<auto-generated`, and
       `@generated` in every code pack;
     - vendored directories: Go's `vendor/` (next to a `vendor/modules.txt`),
       PHP's and Ruby's `vendor/`, Rust's `vendor/` (from `cargo vendor`).
   - `codix.toml` gains `edits.generated`, a list of gitignore-style patterns
     (shared layer).
   - The rule: codix edits what a person would edit by hand. A file that one
     of these conventions marks as not to be edited is refused, whoever marked
     it.
   - Checked at planning time on the files that have sites, which planning
     reads anyway, so nothing is stored in the index.
4. **Overrides.**
   - Given at planning time, one condition each.
   - Listed in the preview with their sites.
   - Never applied to parse-error regions. There is no `--force`.
5. **Errors.** `ErrorReport` gains `sites`, a list of locations: an additive
   change to the error schema.

**Tests:**

- each check, on the languages whose rules differ;
- each override, and that it shows in the preview;
- an override never allows a parse-error site;
- `.gitattributes`, build and `codix.toml` patterns.

### 3.5 `rename` within a file

1. **Command.**
   - `rename <symbol> <new-name>`. The symbol is given by ID, path part, name
     or location; a local only by location.
   - A location on a free reference resolves the way the name would.
   - Flags: the overrides of 3.4, and `--all-overloads`.
2. **Sites at tier 2:**
   - the definition's name;
   - the references bound to it in its file.

   Related symbols:
   - **Types.** A type's rename includes its constructors and destructors, when
     the pack names them after the type, and their references. Renaming a
     constructor renames its type.
   - **Overloads.** At tier 2, a reference binds to the overload set, not to
     one overload. Renaming one of several overloads is refused with
     `tier_too_low`, with a hint naming `--all-overloads`, which renames the
     set.
3. **Unresolved sites** refuse the plan with `unresolved_sites` (3.4), since
   leaving them would break the code:
   - cross-file: free or uncertain references with the name in other files,
     for a symbol visible outside its file;
   - same file, unbound: uncertain references, and member access through
     another receiver, such as `other.total()`.

   With `--exclude-unresolved`, the preview edits the bound sites only and
   lists the unresolved ones as excluded, under the override. A local, a
   file-private symbol, or a name no other reference uses has none, and gets
   its preview directly.
4. **Textual mentions**, listed in the preview and never edited: whole-word
   matches outside the sites, in comments, strings and macro bodies (Javadoc,
   `#define`, `println!("{total}")`). They do not refuse the plan.
5. **Tier 1.** Refused with `tier_too_low` unless `--textual` is given. The
   preview then holds the whole-word matches of the name in the definition's
   file, each one `textual`. Every check except `shadowing` still runs.
6. **Frontends.** `rename` is in the dispatch table, with a description, CLI
   flags, an MCP tool and schema snapshots.

**Tests:**

- per language: a local, a parameter, a member, and a type with constructors;
- each category of unresolved site refused, then edited around with
  `--exclude-unresolved`; textual mentions listed;
- overload refusal, and `--all-overloads`;
- a Java public class refused with `renames_file`;
- `--textual` on the test-only tier 1 pack;
- daemon parity (`live_`).

### 3.6 `apply`

1. **`apply <id>`.** An unknown ID fails with `unknown_preview` (exit 4).
2. **Under the write gate:**
   1. **Journal recovery** (step 4).
   2. **File checks.** If every planned file's hash is unchanged, the planned
      edits are used. Otherwise:
      1. the changed files are brought up to date in the index;
      2. the preview's operation reruns with its stored request; its
         pre-flight refusal, if any, is returned as is;
      3. the new edit set is accepted if it touches the same files, with the
         same number of sites per file, and each region, in order, has the
         planned content;
      4. a region whose content changed, or a new site (a new reference to
         the renamed symbol), fails with `stale_preview` listing those sites;
      5. new excluded sites are reported in the result, not refused.

      An `undo` preview is never rebased: any change is `stale_preview`.
   3. **Journal entry.** It holds the preview ID, the operation, the state
      `writing`, and for each file its path, original bytes, original hash and
      new hash. It commits durably (see Choices) before any write. The journal
      keeps the last 20 entries.
   4. **Writing each file.**
      1. The new content goes to `.<name>.codix-<id>.tmp` in the same
         directory, with the original's permissions, and is fsynced.
      2. Just before the rename, the target is hashed again. If it differs,
         the files already replaced are restored from the journal and the
         apply fails with `stale_preview` naming the file.
      3. The rename. On Windows a sharing violation is retried about 10 times
         over 1 s. A file that stays locked restores the originals and fails
         with `file_locked` (exit 4).
      4. A symlink keeps pointing where it did: codix writes the canonical
         path.
   5. **Index.** Index and manifest are updated from the new contents, parsed
      from memory, with stats from the written files, in one transaction. The
      journal entry becomes `done`, the preview is deleted, and aliases are
      written (3.7).
3. **Result:** files changed, sites, the journal entry, and a hint naming
   `undo`.
4. **Crash recovery.** It runs whenever the write gate is taken: at daemon
   start, and in-process before scans and applies. An entry left in `writing`
   is handled file by file:
   - a file at its new hash is restored;
   - a file at its original hash is left alone;
   - a file at any other hash is left as it is, with the warning
     `recovery_conflict`.

   Leftover temp files are removed, the entry becomes `rolled_back`, and the
   warning `apply_rolled_back` names the preview.
5. **Self-writes.** The watcher finds the new stats equal to the manifest's
   and does not reparse. The test from 2.3 is reused for `apply`.
6. **Test hook.** `CODIX_TEST_CRASH_AFTER=<n>` aborts the process after the
   n-th rename, for tests only (documented like `CODIX_TEST_MAX_WATCHES`).

**Tests:**

- rebase onto a file changed outside its regions;
- `stale_preview` when a region changed, and when a new reference appeared;
- a file changed between the check and its rename;
- the process killed after each rename of a three-file apply: every file is
  original or fully edited, and the next command restores the originals;
- `recovery_conflict`;
- no reparse after an apply with a daemon (`live_`);
- `file_locked` on Windows, with a file held open without delete sharing (CI).

### 3.7 Symbol aliases (from 4.5)

1. **`aliases` table**, migration 7: old ID (key), new ID, creation time,
   journal entry.
2. **Written by `apply`** for every symbol whose ID changed: the renamed
   symbol, its descendants (their qualified names change) and the constructors
   renamed with a type. Old and new symbols are matched through the edit set's
   offset mapping. Chains collapse: aliases that pointed at an old ID now point
   at the new one.
3. **Read queries** (`def`, `refs`, `show`, `outline`) given an aliased ID that
   no live symbol has answer for the new ID, with the note `symbol_renamed`
   naming it. A live symbol always wins.
4. **Edit commands** given an aliased ID refuse with `symbol_renamed` (exit 4)
   and the new ID.
5. **Expiry.** Aliases older than 30 days, or beyond the newest 5,000, are
   pruned at each apply.
6. **Undo** removes the aliases its journal entry created (3.9).

**Tests:** read and edit behavior with an old ID, chains, a live symbol
winning, expiry by age and by count.

### 3.8 `previews`, `discard`, expiry

1. **Config.** New local key `previews.expiry` (duration, default `1h`, in
   `.codix/config.toml`).
2. **`previews`** lists the pending previews: ID, operation and target,
   creation time, files, sites, and a state:
   - `ready`;
   - `rebase`: a file changed outside its regions;
   - `stale`: a region changed.

   Stale and expired previews are listed once and then removed: expiry on
   region change.
3. **`discard <id>…`** removes the named previews; **`discard --all`** removes
   all of them.
4. **`apply`** refuses an expired preview with `preview_expired` (exit 4).
   Expired previews are also pruned whenever a preview is created.

**Tests:** expiry with a 1 s setting, each state, discarding one and all, all
three commands through MCP.

### 3.9 `undo`

1. **`undo`** takes the latest journal entry that is `done` and not undone, and
   returns a preview restoring its original contents:
   - one whole-file edit per file, so the diff shows the reversal;
   - each file planned at the entry's new hash.

   If any of those files changed since, it fails with `stale_preview` naming
   them. An empty journal fails with `nothing_to_undo` (exit 1).
2. **Applying it** is a normal journaled apply. It marks the entry undone and
   removes the entry's aliases.
3. **Repeated undos.** An undo is not itself undone: running `undo` again goes
   one entry further back, up to the 20 kept.

**Tests:**

- rename, apply, undo, apply: the original bytes and the original IDs come
  back;
- a second undo reaches the apply before;
- refusal after a file changed;
- undo after a crash recovery.

### 3.10 Phase exit

1. **Round trips.**
   - Corpus: every symbol and local of each corpus file is renamed to a fresh
     name and back, through the planner in memory. The bytes must equal the
     original, with no new parse errors.
   - Benchmark repositories: `benches/roundtrip.rs` takes 1,000 targets with a
     fixed seed in spring-framework and in linux. For each one it plans,
     applies, renames back and applies, then compares bytes and parse errors.
     Refusals are counted by code.
2. **Benchmarks** (`benches/results/0.3.0.json`):
   - cold index with `refs` (target < 30 s) and index size;
   - `refs` p95 through the daemon;
   - `rename` planning p95 and `apply` p95.
3. **LLM benchmark.**
   - About 10 rename tasks: a local, a private method, a field, a type with
     constructors, a refused overload, and a rename after another change.
   - A run succeeds when the checkout's diff equals the expected sites.
   - The harness resets the checkout between runs.
4. **Release.**

## Deviations from the implementation plan

- **Aliases in phase 3** (Known gap 1), without tombstones. Tasks 3.7–3.9
  become 3.8–3.10.
- **No `scopes` table, and no stored references to locals:** they are
  computed per file when needed (see Choices). The design's data model lists a
  `scopes` table.
- **Locals have no symbol IDs.** `def` answers a local in a new `local` field.
- **Windows:** `std::fs::rename` with retries, not `ReplaceFileW`.
- **Rebase by re-planning** instead of moving regions in the new text.
- **Unresolved sites refuse a rename** (`unresolved_sites`, override
  `--exclude-unresolved`), where the design lists and excludes them: a
  reasonable person does not rename a method and leave its callers broken.
- **Rules the plan did not list:**
  - names tied to the file name are refused;
  - overloads are renamed together at tier 2;
  - Go's capitalization is checked;
  - `undo` walks back through the journal;
  - generated code is also recognized by header markers and vendored
    directories declared by language packs, not only by path patterns from
    version control and build descriptors.
- **New codes.**
  - Errors, all exit 4 unless noted: `invalid_name`, `parse_error_region`,
    `renames_file`, `name_collision`, `shadowing`, `visibility_change`,
    `tier_too_low`, `unresolved_sites`, `generated_code`, `stale_preview`, `unknown_preview`,
    `preview_expired`, `file_locked`, `symbol_renamed`, and
    `nothing_to_undo` (exit 1).
  - Warnings: `apply_rolled_back`, `recovery_conflict`.
- **New config keys:** `previews.expiry` (local) and `edits.generated`
  (shared).
