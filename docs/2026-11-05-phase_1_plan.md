# codix — Phase 1 Step-by-Step Plan

Step-by-step plan for phase 1 (core engine) of
`docs/2026-11-04-original_implementation_plan.md`, as that plan requires when a
phase starts. Task numbers and scope are the implementation plan's; this document
adds the order of work, the choices each task left open, the crate versions, and
the steps inside each task. Each task lands as one reviewed change, on its own
branch, with its tests, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check` and the full test suite green.

## Choices made before phase 1

These were checked on 2026-11-05 with a throwaway probe (Rust 1.99.1,
aarch64-apple-darwin), not taken from memory.

| Question | Choice | Evidence |
| --- | --- | --- |
| Toolchain | Rust 1.99.1, edition 2024, resolver 3; components `clippy`, `rustfmt` | Current stable |
| Link-time registration (1.5) | `inventory` | `linkme` fails to compile under `unsafe_code = "forbid"` (`usage of the unsafe link_section attribute`); `inventory::submit!` compiles and registers under it |
| Write lock (1.9) | std `File::lock` / `try_lock` / `unlock` | Stable on 1.99.1; `try_lock` from a second handle reports `WouldBlock` while held. No lock crate |
| Bundled SQLite (1.8) | `rusqlite` `bundled` feature | SQLite 3.54.1, FTS5 and the `trigram` tokenizer available |
| Name search (1.8) | One FTS5 table, `tokenize='trigram case_sensitive 0'`, over `name` and `qualified_name` | Prefix as `LIKE 'p%'` and glob as `GLOB` both use the FTS index (`INDEX 0:L0`, `0:G1`); see 1.8 for fuzzy |
| Grammars (1.12, 1.14) | Crates below, all loaded into `tree-sitter` 0.27.1 | ABI 14 and 15 both accepted by `Parser::set_language` |
| Network filesystem detection (1.9) | `sysinfo` with `default-features = false, features = ["disk"]`: longest mount-point prefix of `.codix/`, then its file system name | Safe API on Linux, macOS and Windows; keeps `unsafe_code = "forbid"` (a direct `statfs` / `GetDriveTypeW` call would need `unsafe` or a platform crate per OS) |
| Error type (1.2) | Hand-written enum with `Display` and `std::error::Error` | Stable codes and hints need custom methods anyway; no `thiserror` |
| Golden tests, CLI tests | Small helpers in `codix-testkit` over `std::process::Command` and `env!("CARGO_BIN_EXE_codix")`; golden files updated with `CODIX_BLESS=1` | Std only; no `insta`, `assert_cmd` |
| Terminal color and progress | `std::io::IsTerminal`, ANSI written directly, `NO_COLOR` honored; one-line progress on stderr | Std only; no `anstream`, `indicatif` |
| Edit distance (1.8) | Hand-written Levenshtein over Unicode scalars | ~20 lines; no `strsim` |
| Benchmarks (1.18) | `harness = false` bench targets timing the release binary | Targets are end-to-end wall-clock figures; no `criterion` or `divan` |

## Order of work

Tasks run in the implementation plan's order. Two dependencies need a decision
on where code first appears:

- **1.11 before any real pack.** Detection is tested with descriptors under
  `codix-testkit/fixtures/`; the real rules arrive with each pack in 1.14.
- **1.12 needs one grammar.** 1.12 creates `codix-lang-java` with its grammar and
  upstream `tags` query only, to drive the parser pool and the corpus runner.
  1.14 completes it (detection rules, kind mapping, full corpus) and adds the rest.

## Tasks

### 1.1 Workspace, CI, release skeleton

1. Root `Cargo.toml`: `[workspace]` with `codix-core`, `codix-provider`,
   `codix-cli`, `codix-testkit`; shared `[workspace.package]` (edition 2024,
   `rust-version = "1.99"`, license `Apache-2.0`, repository
   `https://github.com/imgn-dev/codix`), `[workspace.dependencies]`,
   `[workspace.lints]`.
2. Lints, set once in `[workspace.lints]` and inherited by every crate
   (`lints.workspace = true`):
   - `rust`: `unsafe_code = "forbid"`, `missing_docs = "warn"` (public items of
     library crates), `unreachable_pub = "warn"`.
   - `clippy`: `pedantic` at `warn` (priority -1), with these allowed:
     `module_name_repetitions` (crate-prefixed type names are the convention
     here), `must_use_candidate` (noisy on every getter),
     `missing_errors_doc` (errors are typed codes, documented on the error
     enum). Also `dbg_macro`, `todo`, `unwrap_used` (outside tests) and
     `print_stdout` / `print_stderr` (outside the CLI renderer) at `warn`.
   - CI turns every warning into an error with `-D warnings`.
3. `rustfmt.toml`: `edition = "2024"`, `style_edition = "2024"`; nothing else.
4. `rust-toolchain.toml`: `channel = "1.99.1"`, `components = ["clippy",
   "rustfmt"]`, `profile = "minimal"`. Targets are added in CI, not here, so a
   local build never installs cross targets.
5. `codix-cli`: binary `codix` with clap's `--version` only.
6. Features `default`, `full` and `minimal` on `codix-cli` (the binary crate;
   the root manifest is a virtual workspace), empty until 1.5, so the CI matrix
   runs from the start.
7. `LICENSE` (Apache 2.0), `.gitignore` (`/target`).
8. CI (`.github/workflows/ci.yml`), on push and pull request, matrix
   `ubuntu-latest`, `macos-latest`, `windows-latest`:
   `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
   `cargo test`, and `cargo hack --each-feature --no-dev-deps check`
   (covers each preset and, from 1.5 on, each provider feature alone).
9. Release workflow (`.github/workflows/release.yml`), manual dispatch and
   `v*` tags, building artifacts only (no publishing step):
   - `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` on native
     Ubuntu x86_64 and arm64 runners with `musl-tools` (grammars and SQLite are
     C, so `musl-gcc` is needed),
   - `aarch64-apple-darwin` and `x86_64-apple-darwin` on macOS,
   - `x86_64-pc-windows-msvc` with `-C target-feature=+crt-static`.
   Each job records binary size and the median of 20 `codix --version` runs to
   a JSON file uploaded with the artifact, and to the job summary.
10. Create the private GitHub repository `imgn-dev/codix` and push, after your
    go-ahead for that step.

**Done when** CI is green on all three platforms for every preset and the
release workflow produces all five binaries.

### 1.2 Operation layer, errors and output

1. `codix-core::op`: `trait Operation { type Request: Serialize +
   DeserializeOwned; type Response: Serialize + DeserializeOwned; const NAME:
   &str; fn run(&self, ctx: &Context, req: Self::Request) -> Result<Self::Response,
   Error>; }`. `Context` carries the project (from 1.3) and the cwd.
2. `codix-core::error::Error`: enum with one variant per stable code
   (`no_project`, `not_indexed`, `ambiguous_symbol`, `unknown_symbol`,
   `invalid_config`, `not_supported_in_build`, `usage`, `io`, `internal`);
   `code()`, `cause()` (one line), `hint()`, `exit_code()` per the design's
   table. `ambiguous_symbol` carries its candidates.
3. Exit codes 0 and 1 from the response: each response reports whether it has
   results.
4. `codix-cli::render`: text renderer (`path:line:col` first column, aligned
   columns, footer), JSON envelope `{"schema_version": 1, "command": …,
   "result": …, "warnings": […]}` and error envelope
   `{"schema_version": 1, "error": {"code", "cause", "hint", …}}`.
   Errors print as `error[code]: cause` / `hint: …` on stderr in text mode.
5. Bounding: `Page { limit (default 50), offset }` in requests; responses carry
   `total`; footer `N of TOTAL; next: --offset K`. Sort order: definitions first,
   then same file as the query's anchor, then path, line, column.
6. A stub operation `codix debug-echo`, hidden from `--help`, to exercise
   rendering; removed in 1.17 once real commands exist.

**Tests:** golden text and JSON for the stub with 0, 1 and 60 results; one test
per error class checking the exit code and both renderings; color absent when
stdout is not a terminal.

### 1.3 Project discovery and path identity

1. `Project::discover(cwd, root_override)`: walk up to the first directory
   containing `.codix/` or `codix.toml`; `--root` skips the walk.
   `no_project` (no marker) and `not_indexed` (`codix.toml` but no
   `.codix/index.db`) with the `codix init` hint.
2. `FileId`: root-relative path with `/` separators, on-disk case, symlinks
   resolved. Case-insensitive detection once per project: create a probe file in
   `.codix/` and stat its case-swapped name. On such filesystems the on-disk
   case is read from the directory listing.
3. Symlinks: the walker follows links (`WalkBuilder::follow_links(true)`),
   which detects loops and reports them as errors, logged and skipped; each
   link's target is canonicalized, and one outside the root is skipped.
4. Path rendering: relative to cwd (`../` when outside); JSON adds `root_path`.
   Input paths accepted relative to cwd or to the root (root-relative tried
   second).
5. `--here` (cwd subtree) and `--path <dir>` (repeatable) as a `Scope` in
   requests.

**Tests:** nested projects (inner root wins), symlink loop, symlink out of root,
case-only difference (macOS and Windows CI; skipped on case-sensitive
filesystems with a logged reason, not silently), cwd in a subdirectory,
`../` rendering.

### 1.4 Configuration

1. `codix-core::config::schema`: a static table of `KeyDef { path, kind
   (string, integer, duration, size, map<glob, language>, list<path>), default,
   allowed, description, file (Shared | Local), effect }`.
2. Phase 1 keys:

   | Key | File | Type | Default | Effect |
   | --- | --- | --- | --- | --- |
   | `languages.overrides."<glob>"` | `codix.toml` | language name | — | reindex matching files |
   | `sources.roots` | `codix.toml` | list of paths | — (build providers decide) | reindex build modules |
   | `index.max_file_size` | `codix.toml` | size | `2MB` | reindex files crossing the limit |
   | `index.scan_interval` | `.codix/config.toml` | duration | `10m` | none until the daemon (phase 2) |

   `index.max_file_size` is shared because it changes what is indexed;
   `index.scan_interval` is local because it is a machine preference.
3. Loading: shared file, then local file, local winning; each value keeps its
   origin.
4. `codix config` forms: get, set, `--unset`, `--list [--show-origin]`,
   `--describe [<key>]`, all with `--json`. Writes through `toml_edit`
   (comments and order preserved; file created on first write; `.codix/`
   must exist for local keys, otherwise `no_project`).
5. Validation before any write; `invalid_config` names the valid keys or values.
6. Effects: `set` / `--unset` report the effect text; indexing effects return
   the list of affected files, actually marked for reindex once 1.10 exists.

**Tests:** round-trip preserving comments and key order; unknown key and invalid
value refused with the file byte-identical; `--show-origin`; local overriding
shared; `--describe` output generated from the schema (golden).

### 1.5 Provider framework

1. `codix-provider`: descriptor types (serde, `deny_unknown_fields`) for the
   three kinds: `LanguageDescriptor`, `BuildDescriptor`, `VcsDescriptor`.
2. Registration: `inventory::collect!(ProviderEntry)`; each provider crate
   `inventory::submit!`s one entry holding its descriptor text, kind, name, and
   for logic-bearing providers a `&'static dyn` trait object (`LanguageSupport`
   gives the tree-sitter `Language`; `BuildResolver` for Gradle).
3. Descriptors embedded with `include_str!` from each provider's
   `descriptor.toml`. Each provider crate's `build.rs` parses its descriptor with
   the same `codix-provider` types (as a build-dependency), so a malformed
   descriptor fails `cargo build`.
4. Features on `codix-cli` (the crate that builds the binary): one per provider
   (`lang-java = ["dep:codix-lang-java"]`, …), presets `default`, `full`,
   `minimal` as in the design. `codix-core` depends on `codix-provider`, never
   on a provider.
5. A table of all known provider names (static, in `codix-provider`) so a file
   whose provider is compiled out reports `not_supported_in_build` instead of
   unknown. A test checks that the table and the provider crates agree.

**Tests:** registry contents for `minimal`, `default` and `full` (run by
`cargo hack`); `not_supported_in_build` for a disabled language; a malformed
descriptor fixture makes a `build.rs` fail (test runs `cargo build` on a fixture
crate under `codix-testkit/fixtures/`).

### 1.6 Version control providers

1. `codix-vcs-git`, `codix-vcs-hg`, `codix-vcs-svn`: descriptor-only crates with
   the design's fields. git `nested-file` (`.codix/.gitignore` = `*\n`);
   hg and svn `hint`.
2. Detection: marker as directory or file (`.git` file for worktrees and
   submodules), checked at the project root only.
3. Every matching descriptor applies; skip dirs and honored ignore files unioned.
4. `init` strategy application lives in core (`apply_ignore_strategy`), called by
   1.16; hints are returned in the response, printed once.

**Tests:** git dir, git worktree (`.git` file), submodule; git plus a fixture
Jujutsu descriptor both applying; `.codix/.gitignore` content; hint printed once
when two runs of `init` happen (second run prints nothing new).

### 1.7 Walker and ignore rules

1. `ignore::WalkBuilder` parallel walk: `.codixignore` and provider-honored files
   through `add_custom_ignore_filename`, git's own global/exclude handling
   disabled (`git_global(false)`, `git_exclude(false)`, `git_ignore(false)`) so
   only named files apply; defaults (`.codix/`, `node_modules`, `target`,
   `.venv`, `dist`) as overrides; skip dirs filtered in `filter_entry`, which
   runs before ignore negations can re-include them.
2. Classification per file: over `index.max_file_size` → skipped; binary (NUL in
   the first 8 KiB) → skipped; not UTF-8 → search-only; minified (average line
   length over 300 characters) → search-only. The threshold is a constant,
   covered by a test.

**Tests:** `.codixignore` negation vs skip dir; `.gitignore` honored only when
git detected; non-git project honoring only `.codixignore`; each
classification.

### 1.8 Index store

1. `codix-core::store`: connection opener shared by readers and the writer
   (`journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`,
   `busy_timeout`).
2. Migrations: `schema_version` table, ordered `&[Migration]` applied in one
   transaction each. Migration 1: `files`, `dirs`, `symbols`, `symbols_fts`.
3. `symbols_fts`: external-content FTS5 table over `symbols(name,
   qualified_name)` with `tokenize='trigram case_sensitive 0'`, kept in sync by
   triggers.
4. API: `replace_file(file, rows)` in one transaction; `commit_batch(files)` for
   many; read API on a snapshot (`BEGIN DEFERRED` read transaction per query).
5. Name search:
   - exact: B-tree index on `name`;
   - prefix: `name LIKE 'p%'` on the FTS table (escape `%` and `_`);
   - glob: `qualified_name GLOB` on the FTS table;
   - fuzzy: query split into trigrams, `MATCH '"t1" OR "t2" …'` for candidates
     (limit 500, best `bm25` first), then ranked by Levenshtein distance on the
     name, ties by shared trigram count; queries under 3 characters fall back
     to prefix.

**Tests:** reader snapshot unchanged while a 10k-row write commits;
migration from an empty database; `replace_file` twice gives identical rows;
each match mode, including a transposed-letter typo found by fuzzy.

### 1.9 Write lock

1. `.codix/write.lock` with std `File::lock` (blocking) and `try_lock` polled
   every 10 ms up to the timeout (default 200 ms) for queries.
2. Network filesystem check at project open via `sysinfo` disks: file system
   name in (`nfs`, `nfs4`, `smbfs`, `cifs`, `smb2`, `afpfs`, `webdav`, …) or a UNC
   path on Windows → `Warning::NetworkFilesystem`, added to every response's
   `warnings` (text: one stderr line; JSON: the envelope).
3. `CODIX_TEST_ASSUME_NETWORK_FS=1` forces the warning, for tests only
   (documented as such).

**Tests:** two processes contending (second times out); lock released after
`kill -9` of the holder (Unix) and process termination (Windows); warning in
text and JSON output with the test variable set.

### 1.10 Manifest and change detection

1. `files` columns per the design (path, size, mtime_ns, inode, hash, language,
   parser_version, status). `dirs`: path, Merkle hash over sorted
   (child name, child hash).
2. Scan steps 1–6: walk; stat compare; rehash on stat change; touch updates
   stats only; new or changed → queue; missing → delete rows; parse queue on
   `rayon`; one commit.
3. Merkle skip: a directory whose stat-derived listing hash equals the stored one
   skips its subtree's per-file comparisons.
4. Racy timestamps: a file whose mtime is not strictly older than the scan's
   start time is stored as racy and rehashed on the next scan.
5. Commit under the write lock: recheck each file's hash; changed files
   re-queued (bounded retries, then left pending); a file already at the
   committed hash is skipped, making concurrent commits idempotent.
6. Parser version per file = language pack version + grammar version + query
   hash; mismatch forces reparse.
7. Config effects from 1.4 mark files pending here.

**Tests:** touch without change (no reparse); change within mtime granularity
(caught next scan); rename; delete; two files swapped between scans; two `index`
processes at once giving one consistent result.

### 1.11 Language detection

1. Chain: `languages.overrides` glob → modeline (Vim `vim: ft=`/`filetype=`,
   Emacs `-*- mode: -*-`, first and last 5 lines) → shebang (interpreter name,
   `env` and `env -S` handled) → exact filename → extension → content
   heuristics for `.h` (C++ keywords), `.m` (Objective-C vs MATLAB markers),
   `.pl` (Perl vs Prolog markers).
2. Rules come from descriptors (`filenames`, `extensions`, `shebangs`,
   `modelines`, `heuristics` as named engine behaviors). Objective-C, MATLAB,
   Perl and Prolog are not launch languages: heuristics pick the language name,
   and files of a language with no pack are plain text, search only.
3. Unknown → plain text, search only.

**Tests:** for each step, a file where that step and the next disagree, and the
earlier one wins.

### 1.12 Parser pool and tier 1 extraction

1. Thread-local `HashMap<LanguageName, Parser>` in the `rayon` pool.
2. Per pack: compiled `Query` for `tags`, cached once. Captures
   `@definition.<kind>` / `@name` / `@doc` from the tree-sitter tags convention;
   each pack maps its kinds onto the shared vocabulary in its descriptor.
3. Nesting: parent symbol from range containment of definitions; qualified name
   `Parent.child` (separator per pack: `.` by default, `::` for Rust and C++).
4. Signature: definition node text up to the body node (field name per pack),
   whitespace-collapsed. Visibility from modifier nodes where the pack declares
   them.
5. Confidence: `low` when the definition node contains or is inside an `ERROR`
   or `MISSING` node.
6. Ranges: 1-based line, column in Unicode scalars, plus byte offsets.
7. `codix-testkit` corpus runner: `corpus/<lang>/<case>.<ext>` with
   `<case>.symbols` (one symbol per line: kind, qualified name, line:col,
   signature); `CODIX_BLESS=1` rewrites expectations.
8. `codix-lang-java` created here with grammar and upstream `tags` query.

**Tests:** Java corpus cases for classes, nested classes, methods, fields;
an error-region case with low confidence; a non-ASCII identifier case for
columns.

### 1.13 Symbol IDs

1. `SymbolId { lang, path, qualified_name, hash }`, text
   `lang:path::Qualified.name#hash`; hash = first 4 hex digits of BLAKE3 over
   `kind \0 normalized signature`, extended to more digits on collision within
   the same path part.
2. Parsing: full ID; path part without hash (unique match required); bare
   qualified or simple name (for `def`/`find`); `file:line:col`.
3. Multiple matches → `ambiguous_symbol` with candidates, exit 3.

**Tests:** ID unchanged by body edits and edits elsewhere in the file; changed
by rename, move to another file and signature change; Java overloads distinct;
each input form.

### 1.14 Language packs, tier 1

1. Java and Go complete: descriptor (detection, kind mapping, qualified-name
   separator, body field, visibility), corpus covering every kind the language
   has.
2. Then, one change each: TypeScript (+ TSX), Python, Kotlin (query written
   here), JavaScript, Rust, C, C++, C#, PHP, Ruby.
3. Search-only formats, one change: JSON, YAML, TOML keys (dotted path as
   qualified name); XML elements; Markdown headings (heading path as qualified
   name); SQL `CREATE` statements' object names. Kind vocabulary: `property`
   for keys, `module` for headings, the matching kind for SQL objects.
4. `capabilities` (static part): compiled-in providers, languages with tier.

**Done when** each language's corpus passes and `capabilities` lists it at
tier 1.

### 1.15 Build system providers

1. Migration 2: `modules` (name, root, build system, source roots, test roots,
   parent, notes).
2. `codix-build-maven`: reads `pom.xml` with a small XML reader (crate chosen in
   this task: candidates are `roxmltree` and `quick-xml`; versions checked then);
   modules, parent POMs by `relativePath`, `${…}` interpolation from project
   properties and `project.*`, `build-helper-maven-plugin` `add-source` and
   `add-test-source`; default `src/main/java`, `src/test/java`.
3. `codix-build-gradle`: `settings.gradle(.kts)` `include(...)` and
   `rootProject.name`; `sourceSets { main { java { srcDir(s) } } }` in both DSLs,
   parsed with the Groovy and Kotlin tree-sitter grammars if suitable crates
   exist (checked in this task), else a constrained scanner; anything else
   recorded as an unsupported construct with its location.
4. `status` lists modules and unsupported constructs.

**Tests:** Maven fixtures for multi-module, parent POM, property interpolation,
build-helper sources, conventional fallback; Gradle Groovy and Kotlin DSL
fixtures; an unsupported Gradle construct shown in `status`.

### 1.16 Index commands

1. `init`: create `.codix/`, apply VCS strategies, print hints, run the first
   index. Re-running on an existing project only reapplies strategies and
   scans.
2. `index`: incremental by default, `--full` rebuilds; progress on stderr only on
   a terminal.
3. `status`: indexed, pending, changed since last scan (stat-only check),
   errors, build modules, network filesystem warning.

**Tests:** golden outputs; `init` on a git project; `status` after an edit.

### 1.17 Query commands

1. `find <query> [--exact|--prefix|--fuzzy|--glob] [--kind] [--lang] [--path]
   [--here]`, default mode: exact, then prefix, then fuzzy, stopping at the first
   mode with results (reported in the footer).
2. `def <name>`, `outline <file|dir>` (tree, signatures only), `show <symbol>
   [--context N]`.
3. `grep <regex> [--lang] [--path] [--kind]`: `regex` over indexed files, the
   enclosing symbol per match from the symbols table; `--kind` keeps matches
   whose enclosing symbol has that kind.
4. Freshness: lookups stat-check returned files and reindex changed ones before
   answering; `grep` runs a no-change scan first; lock busy beyond the timeout →
